# Hard audit of QEVA 0.3

This audit treats the supplied 0.3 ZIP as evidence, not as intent. Its self-checks passed, but several important claims were implemented only as interface language or sketches.

| Finding in 0.3 | Why it matters | Resolution in 0.4 |
|---|---|---|
| Most objects stopped at a textual framework and unpinned assumptions. | “From first principles” was not traversable. | 84 foundational switchboard objects—including each major ZFC axiom/schema—plus 32 new revisions that pin framework/dependency boundaries. |
| The map showed only 25 of 32 objects. | The visual map was not the archive map. | The logical atlas is generated from every current record: 116 of 116. |
| History referenced missing objects and omitted several branch controls. | Links and filters were incomplete. | Every historical QEVA reference and source reference is validated; branch controls derive from data. |
| Records mentioned Protocol 0.1 while declaring object version 0.2. | Readers could not know which semantics governed a record. | Legacy bytes remain preserved; superseding revisions consistently name the current protocol boundary. |
| All 32 objects were editorial; there was no formal artifact. | Verification labels did not demonstrate an executable path. | One deliberately tiny Peano rewrite certificate is replayed by the verifier; everything else remains honestly editorial. |
| Three API wrappers fetched one page and stopped. | That is a demo, not an ingestion system. | Harvester v1 adds bounded pagination, retries/backoff, raw-byte storage, request ledger, deterministic IDs, deduplication, checkpoints, rights defaults, Common Crawl discovery, and candidate extraction. |
| Validation checked closure and local links but not the entire release contract. | Generated data could drift from canonical records. | The new verifier checks record shape, exact refs, revision chains, acyclicity, legacy bytes, atlases, history/source refs, generated JS, proof replay, manifests, BagIt, local links, and offline runtime dependencies. |
| Objects had no stable human pages. | A reader could not cite or browse one idea independently. | Every stable ID and every revision gets a static page. |
| Hash files existed without a custody and recovery practice. | Checksums alone do not preserve anything. | BagIt subset, print core, mirror tiers, restore cadence, threat model, and succession procedure are included. |
| The archive was a large monolithic page and the map a crowded fixed SVG. | It would degrade as the corpus grew. | Searchable rows, data-generated lanes, mobile layouts, and drill-down object pages replace the fixed diagram. |
| Beginner explanations and formal statements were not a consistent navigation contract. | “Math for normies” was aspirational. | Every new/current object page leads with plain language, then exact form, example, boundary, assumptions, dependencies, and verification. |

## Conceptual correction

No honest archive can derive all mathematics from one framework-neutral “absolute first principle.” Identity, objecthood, equality, truth, proof, set, type, and structure already depend on a language or metatheory. QEVA therefore uses a **foundation switchboard**: each branch exposes its declared boundary and its bridges to alternative encodings. This is more rigorous than hiding one favored foundation under the word “obvious.”

## Still incomplete by design

- The 116-object graph is a scaffold, not the full mathematical corpus.
- The 37-event timeline is an orientation seed, not a definitive global history.
- Only one claim has a bundled machine-checkable certificate.
- Harvester v1 has not been run at web scale in this package.
- Field taxonomy, historical priorities, translations, and equivalence bridges require specialist governance.
- Long-term survival depends on recruiting genuinely independent custodians, not on repository structure alone.

These are tracked as work, not concealed as finished features.
