QEVA PROTOCOL 0.1

Specify before asserting.

The protocol describes a mathematical record independently of any website, database, theorem prover, or institution.

1. Canonical object

A QEVA record separates identity, context, assumptions, content, dependencies, relations, verification, and provenance. Human explanations are views of the same record, not substitutes for its exact content.

record = {
  identity,
  type,
  context,
  assumptions,
  content,
  dependencies,
  relations,
  verification,
  provenance,
  revision
}

The normative machine schema is qeva-object.schema.json.

2. Truth is qualified

QEVA does not store an unqualified universal flag called true. A mathematical claim is evaluated relative to stated assumptions and a formal context whenever one is available.

S ⊢ P

Read: under formal system S, proposition P is derivable.

Records may instead be conjectural, refuted, empirically supported, context-dependent, or purely expository. Those states must not be conflated.

3. Representations are not identities

The same structure may appear as a formula, recurrence, sequence, graph, algorithm, diagram, or formal term. QEVA records those as related representations rather than silently treating them as different objects.

4. Context-dependent terms stay context-dependent

Words such as “closed form”, “chaos”, and “quasiperiodic” do not have one universal definition across all mathematics. QEVA must attach a definition to its context instead of manufacturing false universality.

5. Immutability

A released record is never silently rewritten. A correction creates a new revision that points to the earlier record. Historical error remains inspectable.

6. Minimal canonical encodings

The archive uses UTF-8 JSON for individual records and UTF-8 JSON Lines for complete sequential export. Digests are release metadata, not eternal identity assumptions; algorithms may be added or replaced as cryptography changes.

7. Versioning

Protocol version 0.1 is intentionally small and provisional. Future versions may extend fields, but a decoder must never reinterpret an older record under new semantics without declaring the conversion.
