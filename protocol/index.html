QEVA PROTOCOL 0.2

Specify before asserting.

The protocol describes records independently of this website, any database, theorem prover, host, or institution.

1. Stable object; exact revision

logical object:   qeva:1:sequence
exact revision:   qeva:1:sequence@1

Object type is metadata, not identity. Every internal dependency is pinned to an exact revision so old records cannot silently change meaning when a dependency is revised.

2. Proof is not truth

Gamma |-S P     derivable in proof system S
M |= P          satisfied in model M

QEVA keeps syntactic derivability and semantic satisfaction distinct. Both require their context to be declared.

3. One record, several views

Each record separates plain explanation, exact formulation, assumptions, dependencies, relations, verification, and provenance. A friendly explanation may improve without pretending to be the exact mathematical object.

4. Context stays explicit

Terms such as closed form, chaos, and quasiperiodic have multiple precise conventions. QEVA records the convention actually used rather than inventing false universality.

5. Released revisions do not mutate

A correction creates a new revision and names the exact revision it supersedes. Historical error remains inspectable.

6. Small permanent core

Individual records are UTF-8 JSON. Complete sequential export is JSONL. A line-oriented TSV catalog is also emitted for low-complexity recovery. Exact encoding and canonicalization rules are summarized in CORE.txt.

7. Protocol evolution

Protocol 0.2 is provisional. New protocol versions may extend or replace representations, but they may not reinterpret old bytes without an explicit migration record.
