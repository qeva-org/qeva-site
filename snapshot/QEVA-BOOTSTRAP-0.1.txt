QEVA BOOTSTRAP 0.1
==================

NAME
QEVA — First Principles Archive

PURPOSE
Preserve explicit mathematical structure so that a future reader can recover what was asserted, under which assumptions, how objects relate, and how strongly each record was verified.

CORE RULE
Start with assumptions. See what follows.

ENCODING
Canonical text is UTF-8. Individual archive records are JSON objects. The complete sequential export is archive/qeva.jsonl: one JSON object per line. Whitespace outside JSON strings is not semantically significant.

CANONICAL RECORD FIELDS
qeva_version  protocol version used to interpret the record
id            stable logical object identifier
revision      immutable revision number
 type         record class
 title        human label
 summary      short description
 status       expository/formalized/verified/open/refuted/context-dependent
 context      mathematical domain and formal-system scope
 assumptions  explicit prerequisites not encoded as dependencies
 content      human explanation, exact statement, optional example/caveat
 dependencies archive objects required to interpret the record
 relations    typed links to related objects or external targets
 verification checking level and method
 provenance   creation, creator, license, source note
 revision_of  previous immutable record when applicable

IDENTIFIERS
Version 0.1 uses logical identifiers of the form:
qeva:1:<type>:<slug>

These names are not cryptographic claims. Release manifests provide integrity digests separately so digest algorithms can change without redefining mathematical identity.

INTEGRITY
archive/MANIFEST.sha256 contains SHA-256 digests for the files in the archive release. SHA-256 is a present release mechanism, not a permanent constitutional primitive. Future releases may add new digest algorithms while retaining old manifests as historical evidence.

TRUTH
QEVA does not define one global Boolean field called TRUE. Mathematical truth is interpreted relative to declared systems and assumptions whenever possible. The archive distinguishes exact definitions, proved results, conjectures, refutations, empirical evidence, and context-dependent terminology.

PRESERVATION
A complete QEVA copy must be freely reproducible. No website, company, domain, database, theorem prover, cryptographic algorithm, or institution is required to be permanent. Mirrors should be independent. Old bytes should be preserved when formats are migrated.

CONSTITUTION
1. Assumptions are explicit.
2. Provenance is permanent.
3. Formal truth is system-relative.
4. Released records are immutable; corrections create descendants.
5. The complete archive is freely reproducible.
6. No implementation is sacred.
7. QEVA must remain reconstructible without QEVA.

Full license texts are stored in LICENSES/.

END QEVA BOOTSTRAP 0.1
