QEVA RECOVERY BOOTSTRAP 0.2
===========================

WHAT THIS IS
QEVA is an archive of explicit mathematical records. This directory is meant
to help a future custodian recover the archive even if qeva.org, GitHub,
Vercel, the original software, or the original organization no longer exists.

START HERE
1. Read ../protocol/CORE.txt.
2. The individual records are ../archive/objects/*.json.
3. The complete sequential export is ../archive/qeva.jsonl.
4. A low-complexity discovery table is ../archive/CATALOG.tsv.
5. Compare files against ../MANIFEST.sha256 and/or ../MANIFEST.sha512.
6. License texts are in ../LICENSES/.

BYTE AND TEXT CONVENTIONS
Files are sequences of 8-bit bytes. Text files use UTF-8. Bytes 0x00 through
0x7F have the same character values as US-ASCII. For non-ASCII characters,
UTF-8 follows the variable-length encoding standardized as RFC 3629. JSON is
used as standardized as RFC 8259. No byte-order mark is written by QEVA.
Lines generated by QEVA end with byte 0x0A (LF).

JSON RECOVERY HINT
A JSON object is enclosed by { and }. Arrays are enclosed by [ and ]. Strings
are enclosed by double quote characters. Name/value pairs use a colon; list
members use commas. The literals true, false, and null are lowercase. QEVA
records in release 0.2 use objects, arrays, strings, integers, and null; they
do not require floating-point numbers for protocol metadata.

IDENTITY
qeva:1:sequence identifies a logical object.
qeva:1:sequence@1 identifies exactly revision 1 of that object.
Old revisions do not silently change. Internal dependencies name exact
revisions.

INTEGRITY IS NOT AUTHORSHIP
A matching digest shows that bytes match a manifest; it does not prove who
created them and it does not prove mathematical correctness. Preserve copies
from independent custodians and compare provenance when authenticity matters.

DATE CONVENTION
Dates written YYYY-MM-DD use the proleptic Gregorian calendar for archival
metadata in this release.

MIGRATION
If these formats become obsolete, preserve the original bytes, create a new
representation, document the transformation, and keep both. Never overwrite
history merely because a newer encoding is easier to use.

END QEVA RECOVERY BOOTSTRAP 0.2
